# 映射配置说明

配置为 UTF-8 JSON，版本为 `1`。未知键、重复 JSON 键、重复字段 ID、检查引用不存在的字段等均会报错，避免拼写错误静默生效。

## Excel 布局

```json
{
  "sheet": "资产负债表",
  "unit": "元",
  "blocks": [
    {
      "id": "assets",
      "label_column": "A",
      "start_row": 6,
      "end_row": 12,
      "period_columns": {"end": "B", "begin": "C"}
    }
  ]
}
```

这是根对象的 `source`。行号和 Excel 列字母按 Excel 常见写法，列字母用大写。扫描范围上限为五万行；默认不扫描整列。

`unit` 只支持 `元`、`千元`、`万元`，所有来源字段使用这个统一金额单位，不跨币种转换。`end` 和 `begin` 是可自定义的期间 ID，单靠 ID 不会识别日期。必须把每个期间的真实表头加入 `metadata`；实际表头要与配置预期一致。

左右两栏报表在同一 `source.blocks` 中配置多个分区。例如负债栏的科目列为 E，期末列 F，期初列 G；参考完整示例配置。每个字段先限定 block 再查找科目。

## 来源标识校验

```json
"metadata": [
  {"cell": "B3", "expected": "你的公司名称"},
  {"cell": "F3", "expected": "元"},
  {"cell": "B4", "expected": "2026-09-30"},
  {"cell": "C4", "expected": "2025-12-31"}
]
```

比较使用单元格原始值转换成文本后的结果，并去掉首尾空白，不按 Excel 的显示格式解释。实际单元格为日期类型时，文本可能是 `2026-09-30 00:00:00`，应据此设置 `expected`；不要只照着屏幕显示日期填写。金额单位及每个使用的期间表头都应设为校验项，双栏表也需分别校验左右两边的期间。

## 按科目和期间定位

```json
{
  "id": "cash.end",
  "source": {"block": "assets", "labels": ["货币资金"], "period": "end"},
  "target": {"placeholder": "cash.end"},
  "min": "0",
  "max": "999999999.99"
}
```

`id` 是程序字段 ID，须以英文字母开始，只使用英文字母、数字、点和下划线。`labels` 可以有多个已确认等义的科目名。只消除空白、全半角差异和末尾冒号，不去掉括号、数字或任意标点。不使用模糊匹配自动填报。

同一个 block 中，任何一个别名匹配到的所有行合起来必须恰好一行；两个别名各自匹配一行也属于歧义。通过缩小 block 或使用固定坐标解决，不取第一行、不自动相加。

`min` 和 `max` 可选，数值单位为 Excel 来源单位。不设置时允许负数，例如未分配利润可能为负。

`blank_zero` 默认为 `false`。明确设置为 `true` 后才把空单元格或纯空白文本视为零，但公式缺失缓存仍然会报错，不会被这个选项掩盖。

## 固定来源坐标

```json
{
  "id": "cash.end",
  "source": {"cell": "B6", "label_cell": "A6", "labels": ["货币资金"]},
  "target": {"placeholder": "cash.end"}
}
```

坐标模式会验证 A6 的科目，然后读取 B6。不能与 `block/period` 混用；该模式日志的期间标记为 `coordinate`，实际期间必须靠 `metadata` 对列标题校验。遇到合并单元格，配置实际保存值的左上角，不把合并区域的空白单元格当作数据。

## Word 占位符目标

```json
"target": {"placeholder": "assets.end", "occurrences": 2}
```

Word 中应输入 `{{assets.end}}`。默认要求出现一次；同一个金额要同时填入正文和表格时，显式设置 `occurrences`。程序统计正文、表格、页眉和页脚的实际出现次数，必须与配置相等。Word 中任何未映射占位符、格式不合法的花括号变量和缺失目标都会失败。

字段可以不设置 `target`，用于只提取和勾稽核对的项目。Word 模板中出现的全部数字占位符仍须有目标映射。

占位符继承其首个文字节点所在 run 的格式；其余文字的 run 保留。如果 Word 把占位符拆成多段，程序仍能识别。占位符应完整位于一个段落中，不跨换行和制表符。

## Word 表格空白单元格目标

```json
"target": {"table": 0, "row": 2, "cell": 1, "expected_text": ""}
```

这里指正文第一个顶层表格、第三行、该行第二个实际 XML 单元格；索引从 0 开始。不能与 `placeholder` 混用。目标仅支持一个段落、没有嵌套表格的单元格。

`expected_text` 为运行前必须匹配的完整原文。空单元格用 `""`；只有下划线时可用 `"________"`；如果单元格已经填有数字，就会因原文不符而停止。空单元格已有空 run 的样式会被复用；若完全没有 run，则插入一个 run，采用该段落的继承样式。

先运行 `inspect-word` 看实际索引和原文。合并单元格的 XML 顺序和视觉列可能不同；不要凭视觉列号猜测。复杂单元格、嵌套表格和普通空行应使用占位符。

## 勾稽规则

```json
"checks": [
  {
    "name": "期末资产负债平衡",
    "left": ["assets.end"],
    "right": ["liabilities.end", "equity.end"],
    "tolerance": "0.01"
  }
]
```

每条规则比较 `left` 各字段原始金额之和与 `right` 各字段原始金额之和。当绝对差额超过容差时失败。左边减右边的有符号差额写入日志。任一参与字段缺失则状态为 `unavailable` 并阻断输出。左右列表内部不能重复引用字段。

至少需要一条检查。推荐配置资产明细合计、负债明细合计、权益明细合计、资产等于负债加权益，并分别检查期末与期初。实际企业存在更多明细时，应替换示例关系，不能沿用简化关系或为了让结果通过而随意放大容差。规则只支持求和等式，不执行任意表达式或 `eval`。

## 输出格式

```json
"format": {"unit": "万元", "decimals": 2, "grouping": true, "negative": "parentheses"}
```

`unit` 默认为来源单位。`decimals` 为 0 至 8，默认 2；`grouping` 控制千位分组，默认 true；`negative` 可为 `minus` 或 `parentheses`，默认 minus。

先按单位精确换算，再按 `ROUND_HALF_UP` 四舍五入。JSON 日志分别记录原始金额、换算金额、舍入金额和填入的文本。舍入后接近零的负数显示为 `0.00`，避免 `-0.00`。

Word 的静态金额单位文本必须与你的输出配置一致。程序不自动更改模板里的公司名称、期间、单位文字或会计叙述。
